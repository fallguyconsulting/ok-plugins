# ok-planner administration

The judgment side of this family's administration — everything the deterministic core beside this document (`admin/converge`) cannot encode. The suite's front door (`/ok`) reads this document when it administers the family; nothing here is a user-facing verb.

The governing rule is ownership: converge freely overwrites what the suite owns — version-stamped, regenerable files — and migration moves retired-layout files into the shape the current skills expect. Anything not suite-owned reaches the owner as a cleanup offer, which the core's `resolve` mode applies on the owner's yes, or as an audit finding (see "Audit the project against the carried version"), whose draft the core's `amend` mode writes on the owner's yes.

## The core's modes

```
bash admin/converge                    # converge: materialize/repair the suite-owned layer
bash admin/converge diagnose           # read-only drift report; exit 0 clean, 1 on drift, 3 when only cleanup offers await the owner
bash admin/converge wire-hooks <group> # consented settings transcription of one hook group: session-start | subagents | lint — see below
bash admin/converge wire-env           # consented settings transcription of the task-tools env entry — see below
bash admin/converge resolve <id> [keep-new|keep-old|--from <draft>]  # one consented cleanup — see below
bash admin/converge amend <config path> --from <draft>  # one consented audit draft of the project's configuration — see "Audit the project against the carried version"
```

The core prints its usage line for `-h`, `--help`, or `help` and exits 0. It refuses any other first argument that names no mode with `converge: <arg> names no mode; nothing written` and the usage line, and exits 1. It refuses a `wire-hooks` with no group, or with a group outside the three, with a usage line naming the groups: each group is its own consent.

`amend` writes the owner's approved draft over one of two files: `.ok-planner/config.json` or `.ok-planner/review/config.json`. It refuses, writing nothing, with `amend: <reason>; nothing written` and exit 1: any other path; a `--from` that names no file; a draft that does not parse as a JSON object; a lint-config draft that `plumbline config-check` flags, where `node` is on PATH, or that keeps the retired `"checks"` key; a review-config draft that lacks `exclude`, `prose_suffixes`, `test_patterns`, or `bug_families`; and a draft identical to the file. It writes the draft through a temporary file and one rename, and prints `written: <path>`.

Converge materializes every file the suite vendors, from one table that diagnose compares against the same rendering:

- the `.ok-planner/` layout: `subjects/` and `practices/` with their generated tables of contents (`subjects.md`, `practices.md`), the design catalogs' generated tables of contents (`design/concepts.md`, `design/stories.md`, `design/decisions.md`) where `design/` exists, all five regenerated by `bin/catalog-toc` on every converge, `audits/subjects/`, `docs/`, and, where `design/` exists, the `audits/` corpus buckets;
- `.ok-planner/CLAUDE.md` and the estate `LICENSE`; the rules files `.claude/rules/ok-planner-cheatsheet.md`, `.claude/rules/ok-cheatsheet.md`, `.claude/rules/plumbline-cheatsheet.md`, and `.claude/rules/plumbline-coding.md`;
- the import file `.claude/rules/ok-concepts.md`, whose fixed content `@../../.ok-planner/design/concepts.md` makes the harness load the concept index whole into every session before its first reply; it carries no stamp, so diagnose compares its bytes;
- the standards `.ok-planner/docs/events.md` and `.ok-planner/docs/technical-writing.md`, and the subject and practice authoring rules at `.ok-planner/practice-definitions.md`;
- the executables, each written with mode 755: `bin/tasks`, the intake module `bin/issues`, the dashboard's service `bin/dashboard`, `bin/review`, `bin/catalog-toc`, `bin/run-tag`, `bin/port-block`, the lint at `bin/plumbline`, `scripts/surface-corpus`, the session-start hook and the lint's edit hook under `.ok-planner/hooks/`, and the subagent-model and subagent-batching hooks at `.claude/hooks/ok-agent-model` and `.claude/hooks/ok-subagent-batching`;
- the dashboard's build at `.ok-planner/dashboard/`: every file of the build the release carried at the family's `browser/dist/`, its `{{OK_PLANNER_VERSION}}` placeholder stamped with the suite version, and the suite-owned ignore file `.ok-planner/dashboard/.gitignore`, whose `*` keeps the placed build out of git;
- the module marker `.ok-planner/package.json`, whose fixed content `{ "type": "commonjs" }` lets the lint and its edit hook run whatever module type the project's root `package.json` declares; it carries no stamp, so diagnose compares its bytes;
- the review estate at `.ok-planner/review/`: its `CLAUDE.md` and `catalog/` overwritten, its `config.json` and `project.md` seeded once and never overwritten; the seeded `config.json` excludes no estate (its `exclude` lists `*.lock` alone, since the review tool itself leaves out the design corpus, the coding standards, the harness settings, the records, and every suite-owned file), lists the events standard and the practices collection under `standards`, and the lint (`node .ok-planner/bin/plumbline`) under `checks` where `node` is on PATH, `[]` otherwise;
- the vendored skills under `.claude/skills/`, `/audit` and `/document` among them, and the agent profiles under `.claude/agents/`.

Converge runs each executable once right after writing it (`tasks --help`, `issues --help`, `dashboard --help`, `review --help`, `catalog-toc --help`, `run-tag`, `port-block --help`, and `plumbline version` where `node` is on PATH). One that fails stops converge with its path named, and converge writes nothing further. Where `node` is not on PATH, converge still writes the lint and its edit hook, skips the lint's run check, prints one `lint:` line saying the lint needs node, and withholds the lint's wiring block, so no hook entry points at a missing interpreter.

**The dashboard's build.** Converge places the build matching the suite version it stamps, never one fetched when the owner opens the page. It writes each file as text. A carried build with no `index.html`, or with a file that does not decode as UTF-8, stops converge with an assertion naming the file. Diagnose reports each placed file that is missing or differs from the carried rendering, and each other file under `.ok-planner/dashboard/` as `stale: <path> is not part of the carried v<version> build`. Converge removes each such file and every folder it empties, and names them on a `removed:` line. Every file there is suite-owned and ignored by git, so none is a consent question. Where `.ok-planner/dashboard/` is a symbolic link, diagnose reports no such file and converge removes none.

Converge also removes retired payloads (the merged `true-up` verb, any `bin/audit-check`, `bin/document-check`, or `bin/surface-reconcile` an earlier release materialized, and the retired surface apparatus below). Converge removes suite-stamped retired files and the retired estate payloads itself, with no offer and no commit check. The commit-first rule binds `resolve` and the `.ok-review/` migration: neither deletes a file that carries uncommitted changes. Idempotent: a compliant project is a silent no-op.

## Wire the hooks and the env entry — consent, then transcription

Every hook executes from the project's own materialized copy through an entry in `.claude/settings.json`. Each entry is owner-declared configuration, written **only** as transcription of the owner's explicit yes, by the core's `wire-hooks <group>` or `wire-env` mode. Diagnose and converge report each group that needs wiring as its own `WIRING NEEDED` block carrying the exact entries and the exact consent command. Present the blocks, ask, and on yes run the command each names. Each block is its own consent: the owner may take one and decline another. Declined means declined: record it in the report and write nothing.

| group | entries | compared by |
|---|---|---|
| `session-start` | `SessionStart`, matcher `startup|clear|compact` (never firing on resume), running `.ok-planner/hooks/session-start` | matcher |
| `subagents` | `PreToolUse`, matcher `Agent|Workflow`, running `.claude/hooks/ok-agent-model`; `SubagentStart`, matcher `*`, running `.claude/hooks/ok-subagent-batching` | matcher |
| `lint` | `PostToolUse`, matcher `""` (every tool), running `.ok-planner/hooks/post-edit.js` | the whole entry, matcher and hooks |
| env (`wire-env`) | `env.CLAUDE_CODE_ENABLE_TODO_TOOLS` set to `"1"` | value |

**The subagent-model rule and its hook.** `.claude/rules/ok-cheatsheet.md` carries the rule that every subagent dispatch names its model — `opus`, `sonnet`, or `haiku` — and that the session model is never a subagent model. It also says which model each kind of job rides: every analytical job (investigation, relevance, enumeration, discovery, classification, compliance reading, the surface extractor, a document Method's leaf agents) and every review, coding, fixing, writing, and architectural-ruling job rides `opus`, and mechanical single-shot lookups ride `haiku`; no suite instruction sends a job to `sonnet`. The rule binds on its own; the hook enforces only that a dispatch names one of the three. `.claude/hooks/ok-agent-model` denies a dispatch with no model, a model outside the three, a fork from a caller whose profile pins no model, a dispatch from a vendored profile agent other than a fork, or a Workflow script whose `agent()` calls name no model or a refused one.

**The batching rule and its hook.** The same rules file carries the rule to issue every independent tool call together in one message. `.claude/hooks/ok-subagent-batching` injects it into every subagent's context at start as `additionalContext`; it blocks nothing and modifies nothing.

**The lint's edit hook.** `.ok-planner/hooks/post-edit.js` runs the lint over the file an Edit or Write touched, limited to the changed lines of a tracked file. A violation (lint exit 2) blocks, so the agent fixes it in the same turn. A lint internal error, such as a malformed config (lint exit 1), exits 1 with the lint's message: an error the user sees that blocks nothing. A project wired under an earlier release, whose lint entry differs, drifts and re-consents. The `lint` group's command also removes the retired entries an earlier release wired for `.ok-plumbline/hooks/post-edit.js`, `pre-write.js`, `stop-review.js`, and `stop-instructions.js`.

**The task-tools env entry.** The Claude 5 model family loads the harness task-tracking tools only when `env.CLAUDE_CODE_ENABLE_TODO_TOOLS` is `"1"`; a sprint's execution shape uses them as a live checklist mirroring the completion report's stages. The entry is project-scoped by design. Hook and env changes take effect in the next session.

### When `.claude/settings.json` is unusable

The core writes no settings entry into a file it cannot read, and prints no `WIRING NEEDED` block for one. Diagnose and converge print a `CLEANUP OFFERED (ok-planner): settings:.claude/settings.json` block that lists each problem, and `wire-hooks` and `wire-env` refuse with the same line. Six states report this way:

| what the core found | what it leaves unwritten |
|---|---|
| the file holds invalid JSON | every entry |
| the file's top level is not an object | every entry |
| `hooks` is not an object | the hook entries |
| `hooks.SessionStart`, `hooks.PreToolUse`, `hooks.SubagentStart`, or `hooks.PostToolUse` is not an array | the hook entries of that event's group |
| an entry under one of those events is not an object, its `hooks` is not an array, or one of its hooks is not an object | the hook entries of that event's group |
| `env` is not an object | the task-tools entry |

## Cleanup offers — consent, then resolve

Diagnose and converge print one `CLEANUP OFFERED (ok-planner): <id>` block for each item converge leaves for the owner. The block says what is there, what the fix does, the recommended answer, and the exact consent command. A block with one fix recommends `accept`. The front door (`/ok`) presents every block in one question and runs the command for each item the owner accepts. `resolve` re-reads the offers first, refuses an id diagnose would not report now, and applies that one fix: it deletes with `git rm` where git tracks the file, so the deletion is staged and recoverable, and moves with `git mv` the same way. A block whose fix deletes or rewrites a path carrying uncommitted or staged-only changes prints an `Uncommitted:` line, and a block whose paths sit behind a symbolic link prints a `Symbolic link:` line. `resolve` refuses such an item, changing nothing, until the owner commits those changes or removes the link and runs `/ok` again. A move discards nothing, so `resolve` moves a file with uncommitted changes as it stands: the `markdown-intake` fix and a leftover's `move` choice never refuse for uncommitted changes. No offer has a choice that discards changes. The consent command quotes the id, so a path with a space stays one argument. Converge again after it. `/ok` records an offer the owner declines as declined, and the next run offers it again.

An id is `<kind>:<path from the project root>`, so it stays the same across diagnose and converge runs:

| id | what is there | the fix |
|---|---|---|
| `collision:.claude/skills/<folder>`, `collision:.claude/agents/<profile>.md`, `collision:.claude/rules/<file>`, or `collision:.claude/hooks/<file>` | the project's own unstamped files at vendored paths, listed in the block, which says whether they differ from the suite's copy; a skill or agent file is the suite's when its last line carries the suite stamp, a rules file or hook when one of its first five lines does, and the import file `.claude/rules/ok-concepts.md` when its bytes match the suite's | delete the listed files and nothing beside them; converge writes the suite's copy, and the folder's other files stay |
| `retired-verb:.claude/skills/<name>` | files the project wrote in a skill folder at a retired name that gets an offer (`plan-sprint-code`, `converge-local`, `converge-cascade`, and the rest of the offered names under "Retired vendored verbs" below), listed in the block, or the whole folder where its `SKILL.md` carries no suite stamp; converge removes the folder's suite-stamped files itself | delete the listed files |
| `settings:.claude/settings.json` | a settings file in one of the unusable states above, each problem listed | write the draft as `.claude/settings.json` |
| `config:<config path>` | a malformed lint config, defects listed | write the draft over it |

A block with a `Draft:` line needs the owner's words or judgment. The front door writes the draft to a scratch path outside the project, shows it, and on the owner's yes passes it as `--from <draft>`. Draft each kind this way. Change nothing the block does not name, and keep every line and entry it does not name as it stands:

- **`review-facts`** — the whole `project.md`: replace each section's instruction line with this project's facts, read from the tree (its root and out-of-scope paths, the commands no agent runs, the helpers the catalogs name, the `## Code rules` list of `.claude/rules/` files that state rules about the shape of code, which accept-list entry A8 enforces, the drive commands); leave a section empty where the project has nothing to say. The checks live in `config.json` `checks` alone. `resolve` refuses an empty draft and a draft identical to the seed.
- **`review-wording`** — the whole `project.md`, each listed line reworded to name the current path. `resolve` refuses a draft that is empty, has a different line count, changes a line the block does not list, or still names `.ok-review` or `.ok-plumbline/` outside a retired script's path.
- **`review-config`** — the whole `config.json`, each listed defect repaired and nothing else changed. `resolve` refuses a draft that still has a listed defect.
- **`rule-file`** — a short project rule holding only this project's own facts: for `defect-issues.md`, each project-only skill, path, accept-list entry, or term the old file names that the cheatsheet's section leaves to the project; for `errors-reach-the-owner-frame.md`, the project's event helper by name and each project practice or rule file the old file cites. Where it names none, the draft is an empty file. `resolve` refuses a draft that is not shorter than the old file, or that repeats any sentence of eight or more words from the suite's text, or whose target replacement file already exists.
- **`settings`** — the whole `.claude/settings.json`, each named key holding the shape the harness reads: an object for the file, for `hooks`, for each hook entry, and for `env`; an array for each hooks event. Keep every other entry exactly as it is: the file is the owner's, and it carries entries no suite wrote. Show the draft as a diff. `resolve` refuses a draft that is unusable in any of the six ways, or that changes or adds an entry the offer does not name.
- **`config`** — the whole lint config, each listed defect repaired, the `"checks"` key dropped, and every other key kept as it is. `resolve` refuses a draft that does not parse, carries a defect `plumbline config-check` reports (a malformed `citations`, `tests`, `lint_checks`, `folders`, or `ports` entry), keeps the `"checks"` key, or adds, drops, or changes a key the offer does not name.
- **`markdown-intake`** — a JSON Lines file with one record per file the block lists to convert, in the record format of `{{ISSUE-FILE-FORMAT}}` in the family's `skills/_shared/artifact-definitions.md`. Read each file whole and carry it field by field:
  - `id`: the id the block lists for the file.
  - `source`: the file's path under history, `.ok-planner/history/issues/<file name>`.
  - `kind`, `category`, and `artifacts`: from the frontmatter. A `kind` or `category` outside the record's lists becomes `human` or `other`, and `problem` names the old value.
  - `route`: the `triage:` value where it names `upstream`, `defect`, `corpus`, or `question`; null otherwise.
  - `opened`: the frontmatter's `opened`, as ISO 8601 UTC ending in `Z`. Append the `Z` where it is missing, and read a date alone as midnight UTC: `2026-01-02` becomes `2026-01-02T00:00:00Z`.
  - `title`: the `# ` heading.
  - `problem`: the `## Problem` section of a filed file, or the narrative of a verified one, the text between the heading and its first `## ` section. Append every other section, under its own heading, except Candidates, Options, Upstream issue, and Ruling.
  - `options`: one `{"text": ...}` object per bullet of `## Candidates` or `## Options`; the intake module assigns the labels.
  - `upstream`: the text of the `## Upstream issue` section, or null.
  - `recommendation`: a marked `> Generated ruling` or `> Recommended ruling` blockquote under `## Ruling` becomes `{"form": "generated" | "recommended", "text": ...}`, the text after the marker's colon with the `>` marks dropped; null where none stands.
  - `ruling`: the owner's own words under `## Ruling`, the section less any marked blockquote and HTML comment, as `{"text": ..., "at": ...}`. `at` is the file's last commit time in UTC, as `TZ=UTC git log -1 --format=%cd --date=format-local:%Y-%m-%dT%H:%M:%SZ -- <file>` prints it, or the drafting time for a file git never committed. Null where no owner text stands.
  - `messages`: empty. Write no `state`, `closed`, or `closed_as`.
- **`tensions`** — a JSON Lines file with one open record per live tension, per the pre-4.0 migration below.

`resolve` reads a JSON Lines draft through the intake module's reader and refuses one that holds no record or a line that is not a JSON object. It refuses a `markdown-intake` draft unless it holds exactly one record per listed file, matched by `source`, each record carrying the listed id, none closed, and each `ruling.text` equal to the owner's text under the file's `## Ruling` once whitespace is normalized. It refuses a `tensions` draft that closes a record. The intake module checks every record before it writes any, in a dry run before resolve moves a file and again as resolve imports, and refuses the whole import, naming each defect, so a refused draft writes nothing.

## Identify overlapping project context

Per the integration contract, surface preexisting project content that overlaps this family's territory — planning, design-record, and decision-log material the suite would now govern — before converging, and never convert it silently. Scan the project root and one level into the conventional doc locations (`docs/`, `doc/`, `design/`, `.claude/rules/`) for:

- planning and record directories beside `.ok-planner/` — `plans/`, `specs/`, `proposals/`, `rfcs/`, `adr/`, `decisions/`, `sprints/`, `backlog*/`, `design/` at the repo root;
- design or decision documents carrying corpus-shaped content — an architecture-decision log, a concepts/glossary document, a requirements or user-story file;
- rules files in `.claude/rules/` other than this family's cheatsheet that state planning or design-doc conventions.

Scan the same locations for coding-style, comment-policy, and lint-convention documents that are not suite-materialized: a hand-written style guide, a CONTRIBUTING section on comments, an alternate lint cheatsheet. For each hit, propose folding its enforceable rules into the lint config (`lint_checks`, `citations`, `ignore`, `tests`), keeping the rest as a project rules file beside the cheatsheets, or retiring the document.

Tell suite-materialized from hand-written by the stamp: everything the suite owns carries a `Materialized by ok-planner v…` line, or the older `Materialized by ok v…`, `ok-plumbline v…`, or `ok-workspaces v…` line. No stamp means it is the owner's, apart from the two fixed-content files, `.ok-planner/package.json` and `.claude/rules/ok-concepts.md`, which are the suite's when their bytes match its copy; the suite's own retired layouts are the migration section's business, not this one's.

For each hit, propose a conversion plan for the owner's consent, naming three outcomes and a recommendation:

- **fold** — corpus material: carry it into `.ok-planner/design/` as concept / story / decision artifacts, executed by `/discover-design` on an empty corpus or a `/plan-sprint` delta on a populated one — never by this administration, which authors no corpus content;
- **keep alongside** — specific design or reference material the corpus deliberately does not hold (interface grammars, schemas, runbooks): leave it where it is and record that it was seen and kept;
- **retire** — superseded: the owner moves it to their own archive; the administration deletes nothing.

Report every hit and its outcome in the administration report, including the ones the owner declined to act on.

## Declare the lint config, in conversation

The lint reads `.ok-planner/config.json`, or, while that file is absent, `.ok-plumbline/config.json` and then a root `.plumbline.json` from an earlier layout; converge moves an old config to `.ok-planner/config.json`, as the plumbline estate's migration below says. An absent config means the defaults. The config is the project's: the core writes it only through `resolve` or `amend`, from an approved draft or an accepted offer, apart from its rewrites of retired estate paths in the citation templates and in `ignore`.

One definition decides whether the config is well formed: the lint's `config-check` subcommand (`node .ok-planner/bin/plumbline config-check [--config <file>]`), which prints each defect in `citations`, `tests`, `lint_checks`, `folders`, `ports`, and `title` and exits 0 clean, 2 with defects. The `config` offer lists its defects, and `resolve` runs it over the owner's draft. Where `node` is not on PATH, the core checks only that the config parses as an object; the lint that reads the keys does not run either.

**Lint checks.** `lint_checks` maps each lint check (`comment-hygiene`, `citation-resolution`, `no-tests`) to `true` or `false`; a check it does not name is on, and so is every check while the key is absent. The lint and its edit hook run only the checks that are on. Converge renders every markdown file it materializes against the same choice: the payload marks each check's rules between `<!-- lint-check: <name> -->` and `<!-- /lint-check -->` lines, converge drops a block whose check is off, strips the marker lines always, and drops a `## ` section the drops leave empty, so the rules text agents read and the lint never disagree. Diagnose compares against the same rendering, so turning a check on or off reads as drift until converge runs. A malformed config renders with every check on and gets the `config` offer. The lint's wiring is offered whatever the switches say; with every check off the lint reports nothing. Diagnose prints a `lint rules:` line when `.claude/rules/plumbline-cheatsheet.md` or `.claude/rules/plumbline-coding.md` is missing, and converge prints one when it writes them. The line names the files and says to turn a lint check off by setting it to `false` under `lint_checks` in `.ok-planner/config.json`.

**Ports.** `ports` maps each `NAME` (upper-case letters, digits, and underscores, not starting with a digit) to the host port a verification stack binds, for `.ok-planner/bin/port-block` to read back by run tag: `{"service": "<compose service>", "port": <container port>}` for a container that publishes the port with no host port given, in the compose project the run tag names, or `{"record": "<path with {tag}>"}` for a dev server that listens on port 0 and writes the port it got to that path. `port-block <run-tag>` prints one `NAME=<port>` line per name, in declared order. With no `ports`, it refuses with exit 2: the project's own stack commands handle isolation.

- **Undeclared citation tags** (the `citation-tags` offer). Tags are owner-declared and never shipped as defaults. Present the listed entries exactly, and say what declaring them buys: an annotation at a governed site becomes a link the lint resolves, and a slug that names nothing becomes a violation rather than a comment nobody checks. A no is a valid state, recorded as declined; the next run offers it again.
- **Malformed config** (the `config` offer): draft the owner's file with each listed defect repaired and nothing else changed.
- **The retired `"checks"` key** (the `config-key` offer): the fix removes the key and nothing else.

## Issue-intake integrity

The intake is `.ok-planner/issues.jsonl`, one record per open issue, and closed records sit in `.ok-planner/history/issues.jsonl`. The intake module at `.ok-planner/bin/issues` reads every record that has an id, keeping fields it does not know, skips only a line that is no record at all, keeps that line in its file on every write, and names it in a note on stderr, so the core checks no record. It reads past a pre-v9 event row in either file and past a markdown issue file directly under `.ok-planner/issues/`, and its note names the `/ok` offer that converts each: `legacy-intake` for the live file, `legacy-archive` for the archive, or `markdown-intake`. The `legacy-intake` offer stands while any line of `.ok-planner/issues.jsonl` is an event row, and the `legacy-archive` offer while any line of `.ok-planner/history/issues.jsonl` is one.

The `markdown-intake` block lists every markdown file. An `open` or `verified` file converts to a record. An `answered`, `retired`, `fixed`, `promoted`, or `repaired` file moves unconverted. A converted file whose frontmatter lacks a field the markdown format required says so on its line, and the draft supplies the field. A file takes its `issue:` value as its id where that value is a slug no other converted file shares and no open issue in the intake carries; while the pre-v9 event log stands, the open issues are the ones its fold imports. Otherwise its id derives from the filename's slug part, with `-2`, `-3`, and so on after a collision with a converted file or an open issue, and its line says the id is derived. Before its first write, resolve refuses, writing nothing and naming each cause: while git's index is locked (the `index.lock` that `git rev-parse --git-path index.lock` names exists); while `issues/` or `history/issues/` cannot be written, or, where `history/issues/` does not exist yet, its nearest existing parent; while `history/issues/` already holds a file of the same name; while a file it moves sits behind a symbolic link; and while a dry run of the import through the intake module (`issues import --dry-run`) refuses a record. Then it moves every markdown file to `history/issues/`, every tracked one in one `git mv` call and each untracked one by rename, imports the drafted records, and removes the emptied `issues/`. It moves a file with uncommitted changes as it stands. Where a move or the import fails after the first move, resolve moves every file back, the tracked ones in one `git mv` call and the rest by rename, removes the folders it created, and stops naming the cause. Markdown files under `history/issues/` stay as written and read as closed. Issue files are not suite-owned, so the conversion waits for the owner's yes.

## Audit the project against the carried version

The core moves every retired layout it recognizes, but it cannot judge the rest of an upgraded project: a setting, path, or reference the carried version no longer supports, or a setting the project newly needs. The front door audits the project for these after the first converge of each `/ok` pass, before it asks the owner anything. The audit reads each tracked project file the suite reads or governs against this document and the carried payload. It writes nothing to the project. It ends in a list of findings, each sorted by the ownership rule into a core rewrite, an `amend` draft, or a report line.

**What it reads.**

| file | read against | a finding |
|---|---|---|
| `.ok-planner/config.json` | `plumbline config-check` and "Declare the lint config" above: the lint reads `citations`, `ignore`, `tests`, `lint_checks`, `folders`, `ports`, and `title` | a key the lint does not read; an `ignore` or `tests` entry, or a citation `file_template`, that names a retired path this document lists or a path the tree no longer holds |
| `## Paths outside the project root` in every sprint under `.ok-planner/sprints/` and `.ok-planner/history/sprints/` | the lint config's `folders` | a folder a sprint lists there that `folders` does not declare |
| `.ok-planner/review/config.json` | the carried `review/seed/config.json` and `review/CLAUDE.md` | a key the seed carries that the config lacks; a key neither the seed nor the directory note names; a path value (`prompts_dir`, `block_sources`, `standards`, `hunt.rotation`, `hunt.extraction`) or a `checks` command that names a path the tree does not hold |
| the hook entries in `.claude/settings.json` | the wiring table above | an entry whose command names a path under `.ok-planner/`, `.claude/hooks/`, `.ok-plumbline/`, or `.ok-workspaces/` that the table does not list and the `lint` group's command does not remove |
| the project's own files under `.claude/rules/`, and every tracked `CLAUDE.md` | the rules files the core materializes (see "The core's modes") and the retired paths and names this document lists: `.ok-review`, `.ok-plumbline/`, `.ok-workspaces/`, `.ok-planner/ceremony/`, the retired binaries, the retired surface apparatus, the retired rules files, and the retired verbs | a line naming a retired path, a retired verb, or a rules file the core no longer materializes |

A folder finding drafts the folder into `folders`, as a path relative to the project root. Where `config-check` would refuse that path, because it lies outside the repository or is not an existing directory, the finding is a report line instead.

**How it sorts each finding.**

- **Core rewrite.** The suite's own retired-layout content: a retired script's path (see "Callers of retired suite scripts"), the plumbline citation templates, and an `ignore` or `exclude` entry naming a retired estate. The core rewrites each with no offer, and diagnose reports each pending one as drift. In the lint config's `ignore`, the core repoints an entry naming a path the plumbline migration moved (`.ok-plumbline/docs/events.md`, `docs/technical-writing.md`, `subjects`, `practices`, or `practice-definitions.md`) to name it under `.ok-planner/`. It removes every other entry under `.ok-plumbline/`, `.ok-workspaces/`, or `.ok-review/`, and every entry naming the root `.plumbline.json` or `.plumbline-budget.json`. In the review config's `exclude`, it removes every entry under `.ok-plumbline/` or `.ok-workspaces/`. The core rewrites an entry only once its estate is gone or its migration is unblocked, and removes none while live worktrees hold the workspaces estate or a retired script a caller still names keeps the estate. An entry naming a retired script with a drop-in belongs to the repoint. Converge prints `rewrote: <config> ignore: <each change>` and `rewrote: <review config> exclude names <entries>`. Diagnose prints `DRIFT: retired layout: <config> — its ignore names <entries>; converge rewrites them` and `DRIFT: stale: <review config> exclude names <entries>; converge rewrites it`. The audit lists each as rewritten by converge, or as pending while diagnose still reports it.
- **`amend` draft.** Any other finding in the project's configuration, `.ok-planner/config.json` or `.ok-planner/review/config.json`. A finding a cleanup offer already covers (`config`, `config-key`, `citation-tags`, `review-config`, `review-standards`, or `review-exclude`) is that offer's, and the audit drafts nothing for it. Write one draft per file: the whole file, each finding in it repaired, and every other key and value kept as it stands. Write it to a scratch path outside the project and present it with the cleanup offers, in the one question. On the owner's yes, run `bash "<payload>/admin/converge" amend <config path> --from <draft>`. Where the core refuses the draft, correct it and ask about that file alone.
- **Report line.** A finding in the project's own rules files, a tracked `CLAUDE.md`, or a `.claude/settings.json` entry outside the wiring table. The suite never edits a rules file or a memory file, and writes the harness settings only through the wiring and `settings` transcriptions and the repoint of a retired script's path, so the audit drafts nothing: the report names the file, the line number, the line, and what the carried version names in its place, and the owner rewords it.

**What `/ok` reports.** Each finding as `audit: <file> — <finding>: <disposition>`, the disposition one of `rewritten by converge`, `pending converge`, `written by amend`, or `declined`, and each report line as `audit: <file>:<line>: <line> — <what the carried version names in its place>`. The audit leaves nothing pending when converge rewrote or `amend` wrote every finding. A declined draft, a core rewrite diagnose still reports, and a report line each leave their finding pending, and `/ok`'s outcome reads `converged` only when none is pending.

## The audit model changed shape

Audits used to be adversarial determinations (`satisfied` | `violated`) carrying an artifact hash and content-anchored citations, re-derived at every sprint close and invalidated by a staleness computation. They are now one-paragraph verdicts on two independent axes — `implementation:` (`supported` | `unsupported`) and `text:` (`compliant` | `noncompliant`) — about a named commit, written by the periodic audit run. Nothing computes staleness, and there are no citations.

The core handles the whole migration on sight; relay each line it reports:

- **The retired audit corpus is removed** (`Retired audit corpus removed:` line). There is no mechanical conversion — turning a citation-bearing audit into a one-paragraph determination requires reading the code, the audit run's own job — so the next `/audit` writes the corpus fresh.
- **The inspection registry is swept**, with the other retired estate payloads, on the `Retired payloads removed:` line.
- **The committed source graph goes with its extractor.** The graph existed so audits could cite code by node identity and hash; with citations gone it has no reader. `graph/` and `bin/source-graph` are swept whole; the graph was mechanically derived, so nothing is lost the sources do not hold.
- **In-flight sprint contracts are brought current.** A sprint still in `sprints/` when the model changed names the retired implementation-audit term, whose clean bar no longer exists. The contract is fixed suite-owned boilerplate and the compliant end state is determined, so the core drops the retired item, renumbers the one below it, fixes the goal rule's item range, and reports the count. Archived sprints keep their old wording.
- **The `certify-all` verb is retired**; the periodic audit replaced it.

Tell the owner after the upgrade that the corpus is unaudited until the first `/audit` run.

## The ceremony verbs are this family's own

`/audit` and `/document` are ok-planner skills. The suite used to own them as a ceremony layer that belonged to no family, administered by the front door's own converge core and administration document, and each ceremony read a contribution from every family's estate. That layer is gone, and so are the ok-plumbline and ok-workspaces families. This family vendors `audit` and `document` under their bare names in every project, beside its other skills, and this document and the core beside it administer them as they administer the rest of the family. The front door administers ok-planner alone; it carries no layer of its own.

## The surface apparatus changed shape

The public-surface machinery used to be three artifacts kept consistent by a reconciler tool: a JSON **surface declaration**, a prose **surface guidance**, and per-kind committed **member lists** at `surface/members/<kind>` — with the audit writing a **stamped ruling** at `audits/surface/ruling.json` and `bin/surface-reconcile` comparing it all against the tree. That apparatus is retired. The public surface is now one owner-authored prose document at `.ok-planner/surface/surface.md` — the **surface intent** — plus a per-run **surface extraction** at `.ok-planner/audits/surface/extraction.json` an audit subagent writes each run.

The core handles the migration on sight. On any converge over a legacy estate, the sweep removes:

- `.ok-planner/surface/surface.json` — the retired declaration.
- `.ok-planner/surface/guidance.md` — the retired guidance.
- `.ok-planner/surface/members/` — every per-kind committed member list.
- `.ok-planner/audits/surface/ruling.json` — the retired ruling.
- `.ok-planner/audits/surface/extraction.json` — only when it sits beside the retired apparatus above; the next `/audit` writes a fresh one. An extraction on its own is the current audit's committed record and stays.
- `.ok-planner/bin/surface-reconcile` — the retired tool.

The `.ok-planner/surface/` directory itself stays — the intent document lives there. Where the intent is missing after the sweep, converge prints an advisory line: the next `/audit` run files one intake issue asking the owner to author it, and the story track treats every element as internal until the intent lands.

## The documentation run runs no validator over its own corpus

The documentation ceremony used to end with a Check stage that ran `.ok-planner/bin/document-check` and refused completion on a non-zero exit. The stage and the tool are retired: the orchestrator constructs the corpus, presents, and stamps; nothing sits in its hand with a pass/fail exit. A malformed corpus is rewritten whole by the next `/document` run — the corpus is a full-reassessment-per-release artifact (see `.ok-planner/design/decisions/full-reassessment-per-release.md`), so drift self-corrects as audit drift does.

The core removes any `.ok-planner/bin/document-check` an earlier release materialized and reports it on a `Retired binary removed:` line. Nothing to consent to.

- Does not write an owner file in place.
