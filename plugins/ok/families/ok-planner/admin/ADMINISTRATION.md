# ok-planner administration

The judgment side of this family's administration — everything the deterministic core beside this document (`admin/true-up`) cannot encode. The suite's front door (`/ok`) reads this document when it administers the family; nothing here is a user-facing verb.

The governing rule is ownership. Every true-up brings the whole estate to the layout the current skills read: it ports what they still use, archives under `.ok-planner/history/` what they no longer use, and removes only what git or the suite can restore. Diagnose prints all of it as one plan, each destructive step marked. Where the plan holds a destructive step, the owner answers once, go ahead with all of it or abort, before true-up writes anything; a plan with no destructive step runs with no question. After the plan runs, the owner answers the input questions: a value only the owner can give, a draft only the owner can approve, the wiring of the harness settings, and each check finding (see "Check the project against the carried version").

A session whose `/ok` text predates the plan runs a bare true-up against this core, which refuses where the plan holds a destructive step: it writes nothing and tells the session to run `/reload-plugins`, then `/ok` again. The reloaded `/ok` shows the plan and asks.

## The core's modes

```
bash admin/true-up diagnose                               # read-only: prints the plan, the input questions, and the wiring blocks; exit 0 clean, 1 while the plan holds a step or wiring is pending, 3 when only input questions await the owner
bash admin/true-up                                        # applies the plan where it holds no destructive step; refuses, writing nothing, where it holds one
bash admin/true-up --go-ahead <plan id> [--drafts <dir>]  # applies the plan diagnose printed under that id, on the owner's go-ahead
bash admin/true-up show <path>                            # read-only: the diff of the rewrite the plan lists for <path>
bash admin/true-up resolve <id> [--from <draft>]          # one answered input question — see "Input questions"
bash admin/true-up amend <config path> --from <draft>     # one approved draft of the project's configuration — see "Check the project against the carried version"
bash admin/true-up wire-hooks <group>                     # consented settings transcription of one hook group: session-start | subagents | lint — see below
bash admin/true-up wire-env                               # consented settings transcription of the task-tools env entry — see below
bash admin/true-up check-range <first> <last>             # read-only check of a port range the owner names, as the port registry checks it, before the port-range draft — see "Draft each answer this way"
```

The core prints its usage line for `-h`, `--help`, or `help` and exits 0. It refuses, with `true-up: <reason>; nothing written` and the usage line and exit 1: a first argument that names no mode; an argument of true-up other than `--go-ahead` and `--drafts`; a `--go-ahead` or `--drafts` given without its value or given twice; and `--drafts` without `--go-ahead`. It refuses a plan id that is not 12 hex digits, and a `--drafts` that names no folder. It refuses a `wire-hooks` with no group, or with a group outside the three, with a usage line naming the groups: each group is its own consent.

`amend` writes the owner's approved draft over one of two files: `.ok-planner/config.json` or `.ok-planner/review/config.json`. It refuses, writing nothing, with `amend: <reason>; nothing written` and exit 1: any other path; a `--from` that names no file; a draft that does not parse as a JSON object; a lint-config draft that `plumbline config-check` flags, where `node` is on PATH, apart from a retired object form of `ports` kept exactly as the file holds it; a lint-config draft that keeps the retired `"checks"` key, or that drops a citation tag the file declares and the `citation-tags` question would add back, with `amend: the draft is refused: it drops the <tags> citation tag(s) .ok-planner/config.json declares; draft it again from the file as it stands; nothing written`; a lint-config draft whose `port_range` differs from the file's and reaches the machine's ephemeral range, as the port registry checks it, with `amend: the draft is refused: port_range <first>-<last> reaches the machine's ephemeral range, which starts at <n>; nothing written`; a review-config draft that lacks `exclude`, `prose_suffixes`, `test_patterns`, or `bug_families`; and a draft identical to the file. It writes the draft through a temporary file and one rename, and prints `written: <path>`.

`check-range <first> <last>` writes nothing. It checks a range as the port registry checks it, with `.ok-planner/bin/ports check-range`, and prints its answer: the range's size, each port of it on the block list with what uses it, and how many of its ports remain to lease. It refuses, with `check-range: <reason>` and exit 1, a bound that is not an integer from 1025 to 65535, a `first` above `last`, and a range that reaches the machine's ephemeral range, naming both numbers.

`show <path>` writes nothing. It prints the unified diff of the rewrite the plan lists for that path, and refuses, with `show: the plan rewrites nothing at <path>`, a path the plan does not rewrite.

True-up materializes every file the suite vendors, from one table that diagnose compares against the same rendering:

- the `.ok-planner/` layout: its folders (`sprints/`, `sketches/`, `subjects/`, `practices/`, `docspec/`, `docs/`, `history/sprints/`, `history/sketches/`, `history/issues/`, `review/catalog/`, `review/runs/`, and, where `design/` exists, `design/concepts/`, `design/stories/`, and `design/decisions/`), and the generated tables of contents `bin/catalog-toc` regenerates on every true-up: `subjects.md`, `practices.md`, the docspec index `docspec.md`, and, where `design/` exists, `design/concepts.md`, `design/stories.md`, and `design/decisions.md`;
- `.ok-planner/CLAUDE.md` and the estate `LICENSE`; the rules files `.claude/rules/ok-planner-cheatsheet.md`, `.claude/rules/ok-cheatsheet.md`, `.claude/rules/plumbline-cheatsheet.md`, and `.claude/rules/plumbline-coding.md`;
- the import file `.claude/rules/ok-concepts.md`, whose fixed content `@../../.ok-planner/design/concepts.md` makes the harness load the concept index whole into every session before its first reply; it carries no stamp, so diagnose compares its bytes;
- the standards `.ok-planner/docs/events.md` and `.ok-planner/docs/technical-writing.md`, the stack helpers' reference document `.ok-planner/docs/stack-helpers.md`, and the subject and practice authoring rules at `.ok-planner/practice-definitions.md`;
- the executables, each written with mode 755: `bin/tasks`, the intake module `bin/issues`, the dashboard's service `bin/dashboard`, `bin/review`, `bin/catalog-toc`, the stack helpers (the tag generator `bin/run-tag`, the port registry `bin/ports`, the docker sweep `bin/docker-sweep`, and the process-group helper `bin/run-group`), the reference stack tool `bin/stack`, the lint at `bin/plumbline`, the corpus surfacer `scripts/surface-corpus`, the session-start hook and the lint's edit hook under `.ok-planner/hooks/`, and the subagent-model and subagent-batching hooks at `.claude/hooks/ok-agent-model` and `.claude/hooks/ok-subagent-batching`;
- the port registry's block list `.ok-planner/bin/ports-blocklist`, the ports that protocols, apps, and services use by default, which `bin/ports` reads beside itself together with the machine's `/etc/services`;
- the dashboard's build at `.ok-planner/dashboard/`: every file of the build the release carried at the family's `browser/dist/`, its `{{OK_PLANNER_VERSION}}` placeholder stamped with the suite version, and the suite-owned ignore file `.ok-planner/dashboard/.gitignore`, whose `*` keeps the placed build out of git;
- the module marker `.ok-planner/package.json`, whose fixed content `{ "type": "commonjs" }` lets the lint and its edit hook run whatever module type the project's root `package.json` declares; it carries no stamp, so diagnose compares its bytes;
- the review estate at `.ok-planner/review/`: its `CLAUDE.md` and `catalog/` overwritten, its `config.json` and `project.md` seeded once and never overwritten; the seeded `config.json` excludes no estate (its `exclude` lists `*.lock` alone, since the review tool itself leaves out the design corpus, the coding standards, the docspecs, the surface intent, the harness settings, the records, and every suite-owned file), lists the events standard and the practices collection under `standards`, and the lint (`node .ok-planner/bin/plumbline`) under `checks` where `node` is on PATH, `[]` otherwise;
- the vendored skills under `.claude/skills/` and the agent profiles under `.claude/agents/`.

Diagnose names each missing suite file as `DRIFT: missing: <path>`, and each one that differs from the carried rendering as `DRIFT: stale: <path> differs from the carried v<version> rendering`. True-up writes them all and prints `materialized: <n> files under .ok-planner/ and .claude/ (v<version>), each skill folder carrying LICENSE`, counting the files it wrote in that run.

True-up runs each executable once right after writing it (`tasks --help`, `issues --help`, `dashboard --help`, `run-tag --help`, `docker-sweep --help`, `ports --help`, `run-group --help`, `stack --help`, `review --help`, `catalog-toc --help`, and `plumbline version` where `node` is on PATH). One that fails stops true-up with its path named, and true-up writes nothing further. Where `node` is not on PATH, true-up still writes the lint and its edit hook, skips the lint's run check, prints one `lint:` line saying the lint needs node, and withholds the lint's wiring block, so no hook entry points at a missing interpreter.

**The dashboard's build.** True-up places the build matching the suite version it stamps, never one fetched when the owner opens the page. It writes each file as text. A carried build with no `index.html`, or with a file that does not decode as UTF-8, stops true-up with an assertion naming the file. Diagnose reports each placed file that is missing or differs from the carried rendering, and each other file under `.ok-planner/dashboard/` as `stale: <path> is not part of the carried v<version> build`. True-up removes each such file and every folder it empties, and names them on a `removed:` line. Every file there is suite-owned and ignored by git, so none is a destructive step. Where `.ok-planner/dashboard/` is a symbolic link, diagnose reports no such file and true-up removes none. True-up prints `placed: the dashboard build at .ok-planner/dashboard/ (v<version>), ignored by git through its own .gitignore` on every run that applies a plan.

The plan also removes the retired payloads: the retired vendored skills (see "Retired vendored verbs"), the retired shared files and agent profiles, the retired binaries and the retired surface apparatus, and the retired estate payloads each later section names, each under the removal rule (see "The plan"). Idempotent: a compliant project's plan holds no step, and a true-up over it writes no file.

**Live sprints.** A sprint still in `.ok-planner/sprints/` carries the "How to execute this sprint" and "Completion contract" sections the template of the release that planned it laid out. True-up brings current each line of those two sections that a released template held and the carried template no longer holds, line for line: it replaces the run of changed lines around that line with the carried template's lines, keeps beside them every line no template laid out, such as one the owner added, and leaves every other line and section as written. The payload's `admin/retired-boilerplate.json` lists those released lines: every line any released template held in the two sections that the carried template does not. True-up also repoints the lines of a live sprint's build prompt (`-build.md`) that name a path the plumbline migration moved. A sprint file is the project's, so each such change is a destructive rewrite step: `DESTRUCTIVE: rewrites <path>: its boilerplate holds <n> line(s) an earlier release's template laid out; true-up brings them current`, and true-up prints `rewrote: <path>: <the same detail>`. True-up reads and writes the file byte for byte, so a sprint written with CRLF line endings matches no template line and stays as written. Archived sprints under `history/` keep their text.

## Wire the hooks and the env entry — consent, then transcription

Every hook executes from the project's own materialized copy through an entry in `.claude/settings.json`. Each entry is owner-declared configuration, written **only** as transcription of the owner's explicit yes, by the core's `wire-hooks <group>` or `wire-env` mode. Diagnose prints one `wiring: <finding>` line per missing or drifted entry, and diagnose and true-up print each group that needs wiring as its own `WIRING NEEDED` block carrying the exact entries and the exact consent command. Wiring is no plan step, and the plan id does not cover it; a pending entry keeps diagnose at exit 1. Present the blocks, ask, and on yes run the command each names. Each block is its own consent: the owner may take one and decline another. Declined means declined: record it in the report and write nothing.

| group | entries | compared by |
|---|---|---|
| `session-start` | `SessionStart`, matcher `startup|clear|compact` (never firing on resume), running `.ok-planner/hooks/session-start` | matcher |
| `subagents` | `PreToolUse`, matcher `Agent|Workflow`, running `.claude/hooks/ok-agent-model`; `SubagentStart`, matcher `*`, running `.claude/hooks/ok-subagent-batching` | matcher |
| `lint` | `PostToolUse`, matcher `""` (every tool), running `.ok-planner/hooks/post-edit.js` | the whole entry, matcher and hooks |
| env (`wire-env`) | `env.CLAUDE_CODE_ENABLE_TODO_TOOLS` set to `"1"` | value |

**The subagent-model rule and its hook.** `.claude/rules/ok-cheatsheet.md` carries the rule that every subagent dispatch names its model — `opus`, `sonnet`, or `haiku` — and that the session model is never a subagent model. It also says which model each kind of job rides: every analytical job (investigation, relevance, enumeration, discovery, classification, compliance reading) and every review, coding, fixing, writing, and architectural-ruling job rides `opus`, and mechanical single-shot lookups ride `haiku`; no suite instruction sends a job to `sonnet`. The rule binds on its own; the hook enforces only that a dispatch names one of the three. `.claude/hooks/ok-agent-model` denies a dispatch with no model, a model outside the three, a fork from a caller whose profile pins no model, a dispatch from a vendored profile agent other than a fork, or a Workflow script whose `agent()` calls name no model or a refused one.

**The batching rule and its hook.** The same rules file carries the rule to issue every independent tool call together in one message. `.claude/hooks/ok-subagent-batching` injects it into every subagent's context at start as `additionalContext`; it blocks nothing and modifies nothing.

**The lint's edit hook.** `.ok-planner/hooks/post-edit.js` runs the lint over the file an Edit or Write touched, limited to the changed lines of a tracked file. A violation (lint exit 2) blocks, so the agent fixes it in the same turn. A lint internal error, such as a malformed config (lint exit 1), exits 1 with the lint's message: an error the user sees that blocks nothing. A project wired under an earlier release, whose lint entry differs, drifts and re-consents. The `lint` group's command also removes the retired entries an earlier release wired for `.ok-plumbline/hooks/post-edit.js`, `pre-write.js`, `stop-review.js`, and `stop-instructions.js`.

**The task-tools env entry.** The Claude 5 model family loads the harness task-tracking tools only when `env.CLAUDE_CODE_ENABLE_TODO_TOOLS` is `"1"`; a sprint's execution shape uses them as a live checklist mirroring the completion report's stages. The entry is project-scoped by design. Hook and env changes take effect in the next session.

### When `.claude/settings.json` is unusable

The core writes no settings entry into a file it cannot read, and prints no `WIRING NEEDED` block for one. Diagnose and true-up print an `INPUT NEEDED (ok-planner): settings:.claude/settings.json` question that lists each problem, and `wire-hooks` and `wire-env` refuse with the same line. Six states report this way:

| what the core found | what it leaves unwritten |
|---|---|
| the file holds invalid JSON | every entry |
| the file's top level is not an object | every entry |
| `hooks` is not an object | the hook entries |
| `hooks.SessionStart`, `hooks.PreToolUse`, `hooks.SubagentStart`, or `hooks.PostToolUse` is not an array | the hook entries of that event's group |
| an entry under one of those events is not an object, its `hooks` is not an array, or one of its hooks is not an object | the hook entries of that event's group |
| `env` is not an object | the task-tools entry |

## The plan

Diagnose builds the plan from the tree as it stands: every step a true-up would take, in the order the true-up applies them. It prints one line per step, then the estates the plan leaves alone, then its notes, then the input questions and the wiring, and closes with the plan's summary:

- `DRIFT: <step>` — a step that destroys nothing: writing or regenerating a suite file, creating a folder, seeding a file where none stands, moving a file to its current live path, removing machine-local suite content or an OS or interpreter cache, regenerating a catalog table of contents whose first line marks it generated, or filing an intake issue.
- `DESTRUCTIVE: <step>` — a step that deletes a file, moves a file into the archive, or rewrites a file a person edited, which is every file but a suite-owned file that still carries its stamp or its fixed content. An intake conversion, a worktree removal, and a branch deletion are destructive too.
- `  Show: <command>` under a step — a command that prints what the step would archive or convert, or, for a rewrite, `true-up show <path>`, which prints the rewrite's diff. An archive step's `Show:` is `git -C <root> diff HEAD -- <paths>` where a path carries uncommitted changes, and `cat -- <paths>` otherwise.
- `  Draft: <what the draft holds>` under a step — a step that needs a draft only the session can write (see "Drafts the plan needs").
- `blocked: <why>` — an estate the plan leaves alone until the owner settles something in git, such as unmerged paths, tracked files missing from the working tree, or a worktree that is not clean. A blocked line holds back only that estate.
- `left: <why>` and `retired script kept: <path> — named by intake issue(s) <ids>` — what the plan leaves as it stands, and why.
- `PLAN: <n> step(s), <d> destructive; plan <id>` — the closing line, printed on every diagnose. The id is the first 12 hex digits of the sha256 digest of the sorted step lines.

Diagnose exits 1 while the plan holds a step or a blocked line, or wiring is pending; 3 when only input questions remain; 0 when the project is clean. It ends with `Diagnosed ok-planner at <root>: the plan above; nothing written.`, or, at exit 0 or 3, with the project in agreement with the carried version and, at exit 3, the questions awaiting the owner's answer.

**The go-ahead.** A bare `true-up` applies a plan that holds no destructive step. Where the plan holds one, it prints each `DESTRUCTIVE:` line, writes nothing, and exits 1 with `true-up: the plan holds <d> destructive step(s), and the owner has not said go ahead; nothing written. Run /reload-plugins, then /ok again.` `true-up --go-ahead <plan id>` recomputes the plan and refuses, writing nothing, with `true-up: the plan changed since diagnose; run diagnose again; nothing written` where the id differs, so a tree that moved between diagnose and the owner's answer cannot slip a different plan through. Before its first write, an apply checks every step's refusal conditions and refuses, writing nothing, with `true-up: <each cause>; nothing written`: git's index is locked; a path the plan touches carries unmerged changes; a folder the plan writes cannot be written; a path the plan moves a file to already stands; a draft a step needs is missing or refused; the intake module's dry run of a conversion refuses a record; `.ok-planner/config.json` is absent while a blocked `.ok-plumbline/` estate holds the project's lint config, so the new lint would run without the project's citation tags; or a blocked `.ok-plumbline/` estate holds `subjects/`, `practices/`, `subjects.md`, `practices.md`, `audits/`, or `budget.json`, or a root `.plumbline-budget.json` stands beside it, which the review tool the plan writes no longer marks `corpus` or `record`. Then it applies every step in order, regenerates the catalog tables of contents, prints the input questions and the wiring blocks that remain, and ends with `Trued up ok-planner at <root> (v<version>).`

The plan applies the intake conversions before any step that files an issue through the intake module, so no filing meets the module's refusal of an earlier layout partway through a plan. It applies its rewrites and its filings after every move.

**Abort.** On the owner's abort, the session runs nothing, and the project stays on the suite version its stamps record. Its vendored copies read the layout it has, so it keeps working at that version until the owner trues it up.

**The removal rule.** Every deletion in the plan follows one rule. A tracked file that matches `HEAD` is removed with `git rm`, so the removal is staged and git keeps the file. An untracked file that carries its suite mark (its stamp, the suite's `LICENSE` head, the fixed content of `package.json`, or, for a retired estate's `subjects.md` or `practices.md`, a generated heading) is removed, since the suite can write it again. Every other file the plan would remove — one with an uncommitted or staged-only change, one git does not track and the suite did not write, or one that is or sits behind a symbolic link — moves to the archive instead, so true-up never discards uncommitted work. An OS or interpreter cache (`.DS_Store`, anything under `__pycache__/`) and the suite's machine-local content under `.ok-planner/.cache/` and `.ok-planner/dashboard/` hold no work of the project's, and the plan removes them in a `DRIFT:` step. Each removal prints `removed: <path>`, with ` (git rm; staged)` where git tracked the file.

**The archive.** The archive is `.ok-planner/history/`, and an archived piece keeps the path it had. Content inside `.ok-planner/` keeps its path within the estate (`audits/` becomes `history/audits/`). Content outside it keeps its path from the project root, the leading dot of its first folder dropped (`.claude/skills/x/f` becomes `history/claude/skills/x/f`, and `.ok-review/f` becomes `history/ok-review/f`). A move into a taken path merges entry by entry, and a taken file name gets `-2`, `-3`, and so on before its extension. A tracked file moves with `git mv`, so the move is staged. Each move prints `archived: <src> -> <dst>`, with ` (git mv; staged)` where git tracked the file, and a copy kept before a strip prints `archived: a copy of <src> -> <dst>`.

**Rewrites.** Every change the plan makes inside one file folds into one rewrite of that file. Diagnose prints one `rewrites <path>: <detail>` step per change, the first carrying `Show: true-up show <path>`. The apply writes the file once, through a temporary file and one rename, byte for byte, and prints `rewrote: <path>: <detail>` per change. It refuses with `true-up: <path> changed while true-up ran; run /ok again` where the file no longer reads as the plan read it.

**What each kind of content becomes.**

| what is there | the plan's step |
|---|---|
| the project's own unstamped files at a path the suite vendors to under `.claude/skills/`, `.claude/agents/`, `.claude/rules/`, or `.claude/hooks/` (a skill or agent file is the suite's when its last line carries the suite stamp, a rules file or hook when one of its first five lines does, and the import file `.claude/rules/ok-concepts.md` when its bytes match the suite's), or a file at a path the suite writes under `.ok-planner/` that differs from the suite's copy and carries no suite mark | archive the project's files, then write the suite's copy; the step says whether the project's copy differs from the suite's apart from the stamp, and the folder's other files stay |

### Drafts the plan needs

Two steps convert an earlier intake from records the session writes: the markdown intake and the pre-4.0 tensions. Each such step carries a `Draft:` line naming its file. Write each draft to a scratch folder outside the project and pass that folder as `--drafts <dir>` with the go-ahead: `markdown-intake.jsonl` for the markdown intake, and `tensions.jsonl` for the tensions. A missing or refused draft refuses the whole go-ahead before any write. Read `{{ISSUE-FILE-FORMAT}}` in the family's `skills/_shared/artifact-definitions.md` first.

- **`markdown-intake.jsonl`** — a JSON Lines file with one record per file the step lists to convert. Read each file whole and carry it field by field:
  - `id`: the id the step lists for the file.
  - `source`: the file's path under history, `.ok-planner/history/issues/<file name>`.
  - `kind`, `category`, and `artifacts`: from the frontmatter. A `kind` or `category` outside the record's lists becomes `human` or `other`, and `problem` names the old value.
  - `route`: the `triage:` value where it names `upstream`, `defect`, `corpus`, or `question`; null otherwise.
  - `opened`: the frontmatter's `opened`, as ISO 8601 UTC ending in `Z`. Append the `Z` where it is missing, and read a date alone as midnight UTC: `2026-01-02` becomes `2026-01-02T00:00:00Z`.
  - `title`: the `# ` heading.
  - `problem`: the `## Problem` section of a filed file, or the narrative of a verified one, the text between the heading and its first `## ` section. Append every other section, under its own heading, except Candidates, Options, Upstream issue, and Ruling.
  - `options`: one `{"text": ...}` object per bullet of `## Candidates` or `## Options`; the intake module assigns the labels.
  - `upstream`: the text of the `## Upstream issue` section, or null.
  - `recommendation`: a marked `> Generated ruling` or `> Recommended ruling` blockquote under `## Ruling` becomes `{"form": "generated" | "recommended", "text": ...}`, the text after the marker's colon with the `>` marks dropped; null where none stands.
  - `ruling`: the owner's own words under `## Ruling`, the section less any marked blockquote and HTML comment, as `{"text": ..., "at": ...}`. `at` is the file's last commit time in UTC, as `TZ=UTC git log -1 --format=%cd --date=format-local:%Y-%m-%dT%H:%M:%SZ -- <file>` prints it, or the drafting time for a file git never committed. Null where no owner text stands.
  - `messages`: empty. Write no `state`, `closed`, or `closed_as`.
- **`tensions.jsonl`** — a JSON Lines file with one open record per live tension, per "Pre-4.0 tensions" below.

The go-ahead reads a draft through the intake module's reader and refuses one that holds no record, a line that is not a JSON object, or a record that closes its issue. It refuses a markdown-intake draft unless it holds exactly one record per listed file, matched by `source`, each record carrying the listed id and each `ruling.text` equal to the owner's text under the file's `## Ruling` once whitespace is normalized. ## The retired surface apparatus

## The audit and document back-out

`/audit` and `/document` are retired, with no replacement, and so is every artifact and estate folder they alone used. A project's documentation stays current through docspecs: one owner-declared spec per kind of documentation, which every sprint's builders keep current. The plan backs both verbs out of a project:

- It removes the vendored `.claude/skills/audit/` and `.claude/skills/document/` skills, the `ok-audit` agent profile, and the audit's shared prompt `.claude/skills/_shared/implementation-auditor.md`, each under the removal rule; the files the project wrote in either skill folder are archived, as "Retired vendored verbs" says.
- It moves each entry of `.ok-planner/surface/documents/` to `.ok-planner/docspec/<name>`, with `git mv` where git tracks it: `DRIFT: retired layout: <path> — a document type is a docspec now; true-up moves it to <new path>`. Where that docspec path is taken, the plan archives the entry under `.ok-planner/history/surface/documents/`, and the docspec stays. The emptied `surface/documents/` folder goes. A moved document type keeps its text; the docspec index lists it with "where: not declared" or "references: none" until a sprint reshapes it into the docspec form.
- It archives `.ok-planner/audits/`, `.ok-planner/experiments/`, and `.ok-planner/documentation/` whole, one destructive step per folder, into `.ok-planner/history/audits/`, `history/experiments/`, and `history/documentation/`: `DESTRUCTIVE: archives under .ok-planner/history/ <the folder's content>, which no current skill reads: <folder>/ -> <archive folder>/, <n> file(s)`. The move merges entry by entry into what already stands under the archive folder, and the step names each file whose name took a suffix. Its `Show:` is `ls -lR -- <folder>`, or the diff where a file carries uncommitted changes. A folder that holds no file, or only files another step takes, is an empty-folder `DRIFT:` step.
- It deletes the audit's scratch folder `.ok-planner/.cache/audit`, machine-local content, in a `DRIFT:` step.
- It deletes the provenance stamp the retired `/document` wrote at the top of each document it revised: in a tracked file, or an untracked file git does not ignore, whose first non-blank text opens `<!-- Revised by /document at`, the plan deletes the comment through its first `-->`, the rest of that line, and one following blank line, and leaves the rest of the document: `DESTRUCTIVE: rewrites <path>: it opens with the provenance stamp the retired /document wrote; true-up deletes the stamp and leaves the rest`. It keeps no archive copy, since the line is the suite's own text, and leaves an unterminated comment as it stands. The scan skips records, suite files, the retired estates, and the folders the plan archives, and leaves the review facts and both configs to their own rewrites. A memory file, a rules file, a file that is or sits behind a symbolic link, or a file that does not decode as UTF-8 keeps its stamp, and diagnose prints `left: <path> opens with the provenance stamp the retired /document wrote, and true-up deletes none of it: it is <why>` on every run.
- It removes `docs/CLAUDE.md` where its first line is `# docs/ — generated release documents` and a line opens `Materialized by /document at`, under the removal rule. That file tells every session the documents beside it are records never to read, which no longer holds.
- It drops `hunt.extraction`, `hunt.flow_kinds`, and `hunt.flow_area_size` from `.ok-planner/review/config.json`, since `/converge` analysis mode cuts its flow areas from the surface intent: `DESTRUCTIVE: rewrites .ok-planner/review/config.json: hunt names hunt.extraction, hunt.flow_kinds, hunt.flow_area_size; removed`.
- It leaves the surface intent at `.ok-planner/surface/surface.md` in place, and leaves the audit's run ledgers under `.ok-planner/tasks/` as the records they are.
- A bootstrap creates `.ok-planner/docspec/`, whose index reads "none yet", and no audit folder.
