# /port

Produce a complete Plumbline port plan for the current project. The plan enumerates every violation across both checks and the passes needed to make `plumbline .` return clean — ready to hand off to a planner or to execute directly.

Like every proposal verb in this family, it is **read-only**: the plan is printed for the owner to read, and nothing is written into the project unless the owner names an output path in the invocation. Nothing is applied either way.

For the full reference on each phase, see `docs/plumbline-porting-guide.md` in the plugin distribution.

## What this does

1. Runs `plumbline diagnose` to assess installation state.
2. Runs `plumbline .` to count violations per check.
3. Runs `plumbline patterns` to cluster the violations by shape — this is what makes the `comment-hygiene` pass concretely actionable instead of "thousands of them, good luck."
4. Emits a phase-by-phase plan — printed by default, written to a file only when the owner passes a path as the second arg. The plan's goal is **complete**: executing it leaves the lint clean with both checks on. The budget ratchet, which is a strategy for projects that won't do the full sweep at once, is referenced as a fallback in the porting guide, not in the plan itself.

The plan skips the **Adopt** pass when the diagnosis reports `healthy`. It skips each check's pass when that check's count is zero. The total passes always include **Maintain** as the steady-state description.

## Run

```bash
target="${1:-.}"
# Read-only by default: an output path is the owner's explicit ask.
output="${2:-}"
plan_tmp=$(mktemp)

abs_target=$(cd "$target" && pwd)
project=$(basename "$abs_target")

# Prefer the target project's pinned binary, so a cloned converged project plans
# at its own version with nothing installed. Fall back to the carried payload
# with an announcement — porting often runs before the project has an estate.
plumbline_bin="$abs_target/.ok-plumbline/bin/plumbline"
if [ ! -x "$plumbline_bin" ]; then
  plumbline_bin="${CLAUDE_PLUGIN_ROOT:-plugins/ok}/families/ok-plumbline/bin/plumbline"
  echo "note: no vendored binary in this project — planning from the carried payload" >&2
fi

guide_path="${CLAUDE_PLUGIN_ROOT:-plugins/ok}/families/ok-plumbline/docs/plumbline-porting-guide.md"
if [ -f "$guide_path" ]; then
  guide_ref="\`$guide_path\`"
else
  guide_ref="the plumbline porting guide, carried by the ok plugin"
fi

diagnose_out=$(node "$plumbline_bin" diagnose "$target" 2>&1 || true)
diagnose_healthy=false
if echo "$diagnose_out" | grep -q "plumbline diagnose: healthy"; then
  diagnose_healthy=true
fi

audit_out=$(node "$plumbline_bin" "$target" 2>&1 || true)
patterns_out=$(node "$plumbline_bin" patterns "$target" 2>&1 || true)

hygiene_count=$(echo "$audit_out" | grep -c "plumbline/comment-hygiene" || true)
citation_count=$(echo "$audit_out" | grep -c "plumbline/citation-unresolved" || true)
total=$((hygiene_count + citation_count))

{
  echo "# Plumbline port plan — $project"
  echo ""
  echo "Generated by \`/port\`."
  echo ""
  echo "**Goal**: execute this plan and \`plumbline .\` returns clean under both checks (\`comment_hygiene\`, \`citation_resolution\`)."
  echo ""
  echo "Reference: $guide_ref"
  echo ""
  echo "## Current state"
  echo ""
  echo '```'
  echo "$diagnose_out"
  echo '```'
  echo ""
  echo "## Backlog"
  echo ""
  echo "| Check | Count |"
  echo "| --- | --- |"
  echo "| comment-hygiene | $hygiene_count |"
  echo "| citation-unresolved | $citation_count |"
  echo "| **Total** | **$total** |"
  echo ""

  if [ "$total" -eq 0 ] && [ "$diagnose_healthy" = "true" ]; then
    echo "## Result"
    echo ""
    echo "Already Plumbline-clean. Nothing to do."
    echo ""
  else
    echo "## Plan"
    echo ""

    pass=1

    if [ "$diagnose_healthy" != "true" ]; then
      cat <<EOF
### Pass $pass — Adopt

- Run \`/ok\` so the front door's administration converges the family into this project; commit \`.claude/rules/plumbline-cheatsheet.md\`
- Run \`/starter .\`; review the proposed config; save as \`.ok-plumbline/config.json\`; commit
- Verify: the administration's diagnose reports clean

EOF
      pass=$((pass + 1))
    fi

    if [ "$citation_count" -gt 0 ]; then
      cat <<EOF
### Pass $pass — \`citation-unresolved\` ($citation_count violations)

Citation tags are declared in the plumbline config's \`citations\` array. Each violation is a slug that does not resolve.

- Run \`/patterns\` to cluster by tag (\`tag:@concept:\`, \`tag:@story:\`, ...).
- For each tag cluster: triage each slug — fix typos, rename to match an existing artifact, create the missing artifact, or remove the citation if the link is no longer load-bearing.

Verify: \`plumbline .\` reports zero \`citation-unresolved\` violations. Commit.

EOF
      pass=$((pass + 1))
    fi

    if [ "$hygiene_count" -gt 0 ]; then
      cat <<EOF
### Pass $pass — \`comment-hygiene\` ($hygiene_count violations)

Under plumbline's strict rule, comments are not permitted in source files except machine directives (license headers, lint suppressions, build tags), configured citation tags, and JSDoc/GoDoc comments in files carrying the \`@plumbline:allow-docstrings\` opt-in marker. Every violation listed is one of: an obvious deletion (residue, restatement, TODO, divider), a load-bearing constraint that should become an assertion / test / type / name, or a docstring on a public-API surface that warrants the opt-in marker.

Cluster shapes (from \`plumbline patterns\`):

\`\`\`
EOF
      echo "$patterns_out"
      cat <<'EOF'
```

For each cluster:

- `disallowed-prose` / `todo-marker` / `divider` / `commented-out-code` — sample 3-5, confirm the shape, bulk delete.
- `doc-residue` — the comments are JSDoc/GoDoc-shaped but the file is not opted in. If the file is a public-API surface, add `// @plumbline:allow-docstrings` near the top (with `#` for hash-comment languages). Otherwise delete.
- `license-fragment` — comments mention a license but don't match the machine-directive patterns. Reformat so the license header opens with `SPDX-License-Identifier:` or `Copyright`, or delete the residue.
- For each comment that names a real constraint (a `must`/`always`/`requires` style invariant, a deliberate-choice guard), run `/suggest` for per-violation proposals and convert to code (assertion with message, test that fails on violation, type that enforces, function/variable name that carries the intent).

Verify: `plumbline .` reports zero `comment-hygiene` violations. Commit.

EOF
      pass=$((pass + 1))
    fi

    cat <<EOF
### Pass $pass — Maintain (steady state)

- The \`PostToolUse\` hook blocks edits that introduce new violations
- Wire \`node .ok-plumbline/bin/plumbline .\` (and \`budget check\`) into the project's own CI

EOF

    cat <<'EOF'
## Notes for the executor

- Each pass must leave the lint clean for the checks it addresses before the next pass begins.
- The default action for a comment-hygiene violation is **delete**. Conversion to code (assertion / test / type / name) is the right move only when the comment names a real constraint that some downstream agent could break by "simplifying."
- If the project explicitly decides not to do the full `comment-hygiene` sweep at once, the **Ratchet fallback** (`plumbline budget save` + the CI budget-check step) captures a baseline and prevents regression while the backlog burns down opportunistically. The fallback path is documented in the porting guide referenced at the top — it is not part of this plan, because this plan's goal is the clean-state contract.

EOF
  fi
} > "$plan_tmp"

if [ -n "$output" ]; then
  mv "$plan_tmp" "$output"
  echo "Wrote port plan: $output"
else
  cat "$plan_tmp"
  rm -f "$plan_tmp"
  echo ""
  echo "(read-only: nothing was written. To save this plan, re-run naming a path: /port . ./plumbline-port-plan.md)"
fi
echo "Backlog: $total total violations."
```

## After the script runs

The plan was printed; it exists as a file only if the owner named one.
Offer to save it, and — before saving or handing it off — check whether the project uses a plan/spec convention and offer to move or adapt the file accordingly:

- Look for directories like `.ok-planner/`, `.specs/`, `docs/plans/`, `plans/`, `proposals/`, `design/`
- Check the project's `CLAUDE.md` or `README.md` for a documented plan/spec workflow
- If found, ask the user whether to move the file into that convention (matching its naming — date prefix, sequence number, etc.) and whether to reshape headings if the convention expects a specific structure
- If none found, offer `./plumbline-port-plan.md`, and write it only on the owner's yes

If the project has a planning orchestrator (a `/brainstorm`, `/write-plan`, or similar), suggest invoking it with this file as the input.

The plan's goal — `plumbline .` returns clean with both checks enabled — is the binding contract for whatever executes it.
