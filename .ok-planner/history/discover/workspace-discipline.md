# The workspace discipline: three rules that travel together

## Description

ok-workspaces "canonizes workspace hygiene for parallel agent work as three rules that travel together": **one worktree per job**, **one isolated runtime stack per worktree**, **content-addressed artifacts** ("never a mutable tag in a verification path"). The materialized cheatsheet explains the coupling: "Each one makes the next one safe — ship any subset and the isolation story has a hole." The rules are stack-invariant; "their realization is tailored by the project's committed stack profile at `.ok-workspaces/config.json` (detection proposes, the committed file decides)."

Rule 1: every unit of work gets its own checkout on its own branch — directory `<dirPrefix><job>` (default `.ok-workspaces/worktrees/<job>`), branch `<branchPrefix><job>` (default `wt/`). "Never share a working tree between concurrent jobs; never do job work on the main checkout." **Worktrees default to inside the project root** — a deliberate choice with a stated rationale: "a job's checkout should never escape the project it belongs to," and "because a checkout inside the repo must never become content of the repo, true-up writes `.ok-workspaces/.gitignore` covering wherever the profile puts them — scoped to the plugin's own dot-directory, since the ownership rule forbids touching the project's root `.gitignore`." Worktrees elsewhere are "a declaration, not drift."

Rule 2 varies by profile runtime: `docker-compose` — each workspace runs its own compose project namespaced `COMPOSE_PROJECT_NAME=<prefix>-<job>` ("Container names, networks, and volumes all derive from the project name"), host ports parameterized never fixed; `dev-server` — per-workspace port block `basePort + N × portsPerWorkspace` exported via the profile's `portEnvVars` ("a second workspace must be startable without editing the first"); `none` — nothing, with the cheatsheet telling the owner to re-run detection if a runtime appears.

Rule 3 (see `src-tag`): verification artifacts are tagged by source-tree hash; "Never `:latest` or any mutable tag in a verification path — staleness must be unrepresentable, not avoided."

The `/audit` verb sweeps the mechanical residue of all three: mutable tags in test/harness/CI paths (dev-only compose files exempt — "Judge each hit's path honestly"); compose files pinning identity two workspaces would fight over (`container_name:`, fixed host ports, fixed named volumes); worktree/branch naming conformance (including orphaned `wt/` branches with unmerged commits); and src-tag consumption ("A materialized script nothing consumes means rule 3 of the cheatsheet is decorative — finding"). Read-only: "report and stop."

## Observations

- The dev-server port-block formula appears in three places (detect.js defaults, cheatsheet text generated by true-up.js, /open's allocation step) with the N-derivation ("1 + the count of existing `<dirPrefix>*` worktrees") only in /open — the allocation algorithm has no single home.
- The audit's mutable-tag regex (`:latest|:dev\b|:main\b|:stable\b`) is prompt text, not a script — the one ok-workspaces check that could be mechanical is judgment-applied.
