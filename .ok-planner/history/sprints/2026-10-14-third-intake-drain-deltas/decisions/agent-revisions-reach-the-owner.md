# Every agent revision of a shown issue reaches each person as a diff

## Choice

Every agent revision of an issue already routed or ruled reaches each
person as new analysis, whichever ceremony writes it: the intake
records an update message, new to each person until that person reads
the issue, holding each revised field's text before and after. Every
surface that shows a person an update message shows its difference. A
first routing stays silent, and so does a change to link markup alone.

## Rationale

A ruling rests on an issue's premises, so a premise rewritten under a
standing ruling must reach each person who works the intake, whoever
rewrote it. A diff shows exactly what changed, so the update message
needs only one line, and no person rereads a whole problem to find the
edit. A person reads analysis in a session as well as on the
dashboard, so a surface that names the revised fields without their
difference sends the reader back to the whole field. A first
routing already shows the issue as needing a ruling, and a link change
alters no analysis, so a signal for either would only inflate the
count.

## Alternatives

- Only triage's revisions reach the owner — a ruled issue whose problem another ceremony rewrites stays ruled with no signal.
- An agent revision of a ruled issue drops it back to needing a ruling — an agent's act unsettles the owner's ruling.
- The update message narrates each revised field — the owner reads prose about a change instead of the change.
- Only the dashboard shows an update's difference — a session that walks an issue shows that a field changed, not how.
