# Shim conformance is a checkable file property with no check

`decision:hook-shims` — every plugin-root hook is a thin shim that resolves the project root, hands off to the project's materialized copy, and exits silently when none exists — currently holds in all three shipped shims (ok-planner's session-start and user-prompt-submit, ok-plumbline's post-edit.js), but nothing would catch drift. The shim shape is load-bearing: it is what guarantees a project runs the hook version it was trued up to and that editing a plugin checkout can't disturb another project's live session. A shim that quietly grew real behavior would defeat both properties while looking like it works.

Shim conformance is a static property of committed files — deterministic, checkable by comparing each shim against its canonical shape — so the prompt-executed-checks precedent doesn't cap this at a text-presence proof. Separately, the issue's filed alternative ("record prose-governance as permanent") collides with the decision-artifact rules, which recognize only two resting states for an unproven decision: a default with no real alternative (this isn't), or an unenforced intention filed for calibration (the state that produced this issue).

## Options

- **Golden-file conformance check** — a test that each plugin's shipped hooks match the canonical shim shape (byte-comparison against a template, or a structural assertion: resolve-root, exec materialized copy, nothing else). Cheap, deterministic, satisfies the falsifier bar (add a line of behavior to a shim, the check goes red).
- **Record prose-governance as permanent** — requires amending the decision-artifact invariant to admit a third resting state; a corpus-rule change to avoid a small test.

## Ruling

> Recommended ruling (/verify-issues): build the conformance check — a sprint work item adds a golden-file (or structural) test asserting every plugin-root hook matches the canonical shim shape, and `decision:hook-shims`' Proof is rewritten to name it.
>
> Rationale: the check is trivial to build, the property it protects is what makes plugin development safe against live consumer sessions, and the alternative costs more than it saves — bending a corpus-wide invariant to legitimize not writing a small deterministic test.
