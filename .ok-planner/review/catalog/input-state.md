# Family: input and state

What a function does with a value it did not make, and how it changes state other code shares. The file agent enumerates three lists before it judges anything: every value that arrives from outside with every read of it, every conversion of such a value with the guard in front of it, every field two threads share with its lock, and every function that writes more than one durable thing. The close names each list's count.

Every row is read through the accept list, pasted into your prompt. A row's check names the entries it serves; a site whose failure causes none of their harms stands. A fix under any row keeps the file open for another read.

The outside sources are closed: a message payload, a reply body, a parsed file, an environment variable, a command-line argument, a request's path, query, form, or header, and nothing else. A row a query returns, a configuration object the process built, and a value another function of the program computed are not outside values.

| I1 | Outside value read unchecked | Serves A2, A3, A6, and A7, through the harm test below. Coding rules 4 and 7. List every value in the file that arrives from an outside source, then follow each one to every read of it in this file. A read is a key access, an attribute access, a conversion, a comparison against a set, or an iteration. A value stored, forwarded, or compared whole is not read and stays opaque; a `.get` on a value already known to be a mapping is not a read; a value checked once at its entry and read only after that check is one read. The harm test decides which reads are defects. Follow the wrong value forward from the read: where it makes the program do the wrong thing (take a branch it should not, write or delete the wrong thing, reach the wrong target, report work done, read as absence or as an empty answer), the read is a defect. Where the wrong value already ends in a failure the unit's owner frame records, and a check would change only the name of that failure, the read stands, unless an end user supplied the value through the public surface: there it is refused with a message the user can act on (accept list A3). The defect is a read that fails the harm test and whose failure is a bug-shaped raise, a bare `KeyError`, `IndexError`, `TypeError`, `ValueError`, or `AttributeError` with no name (a command-line argument read by position with no count check is such a read): check it at that read and raise the refusal type this file already declares, or the family the function already raises, with a message naming the input and the site. Never a new type, never a check moved elsewhere, never a check on a value already typed. A coercion by what the text looks like instead of the declared type: coerce by the type. A conversion behind a guard that accepts more than the conversion does, so a value passes the guard and the conversion raises bare: use the guard that accepts exactly what the conversion accepts. In a command body: two exclusive flags accepted silently, refuse the pair up front; a validator replaced by one that dropped a bound the old one enforced, restore it. | Fix here where the refusal raises a family the function's callers let propagate to their owner frame. Where the unchecked read is inside a callee in another file, or one ruling on the value belongs in a shared module that several files would import, record a unit on that callee or module. |
| I2 | Outside value built into a path, a URL, or a command | Serves A2. A join whose result reaches a delete, an overwrite, a write, or a command is this row's; a join that only builds a link, a read, or a message stands. An outside value joined onto a directory, interpolated into a URL or a route path, placed in an argument list, or written into a file a shell later sources or a program later parses, with no check that it is what the site needs (a join always fails the harm test: the wrong value reaches a path, a target, or a command): one path segment (no separator, not `.` or `..`, not absolute), a quoted URL segment, an argument that cannot be read as an option, a value escaped for the file's grammar. `rg` the file for the joins and the f-strings that hold an outside value. Check at the site with the idiom the package already uses (`quote(value, safe="")` for a URL segment), and refuse in the family the function already raises. | Fix here. Where the tree should hold one definition of what the value is (a release name, a device identifier) and several files join it, record a unit on that definition. |
| I3 | Shared state read or written outside its lock | Serves A1: a check-then-write, or a lost update, between threads. A read outside the lock that only reports stands, and so does a lock held across a call, which is recorded as a call. Coding rule 3, within one class or one module that owns the state and the lock. List every field two threads share and the lock that guards it. A read that decides a write, or an emit that reports the state, outside the lock the write holds: move it under the lock. A method that writes the field under no lock while another method holds one: take the lock. A flag that guards teardown set by a check-then-set on a bare event: set it under the lock. Elapsed time computed from two clocks, or a deadline compared against a clock other than the one that set it: use one clock. A mark another writer may set cleared unconditionally: clear it conditionally on the value acted on. A lock held across a call out of the process, so every other holder waits on that call: record a call naming the wait, and narrow the lock only where the state it guards is not touched by the call. | Fix here; nothing under this row changes what a method takes, returns, or raises. State shared with code in another file, or a lock another file holds: record a unit. |
| I4 | State change split across separate writes | Serves A1, always. Coding rule 3, within one function that writes more than one row, file, or resource by separate calls, where a failure between the calls leaves a partial result. Make it one change with the primitive in reach: one transaction, one atomic replace (write to a temp path, then rename; the project's facts name the tree's helper), or one batched call. A file written in place with truncate, where a reader may meet it empty or partial: replace it atomically. A value the write records (a digest, a timestamp, a position) read before the transaction that writes it: read it inside. A check-then-write with no row lock and no affected-row count: hold the lock, or read the count and raise on zero. | Fix here. Where the primitive lives in another module and lacks what this write needs (a file mode, a directory target), or the writes span two functions, record a unit on the primitive or on the first function. |
