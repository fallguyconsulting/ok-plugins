# Family: failure paths

What a function does when something goes wrong: what it releases, what it catches, how long it waits, and whether work that repeats survives one failure. The file agent enumerates these lists before it judges anything: every exit of every function that holds something in a long-running process, or that writes stored state; every catch in the file; every wait in a long-running process; every test or listing whose "no" or empty answer the code reads as absence before a write; every loop that releases, removes, or stops more than one thing; and every piece of work that repeats or runs without end. The close names each list's count.

Every row is read through the accept list, pasted into your prompt. A row's check names the entries it serves; a site whose failure causes none of their harms stands. A fix under any row keeps the file open for another read.

| F1 | Exit skips cleanup, or a cleanup masks a failure | Serves A5 and A1. A resource held past the end of a process that ends when its work ends (a command, a script, a one-shot job) stands: the operating system releases it. A skipped cleanup that leaves a partial file or row behind is A1. Coding rule 4, within one body. List every exit of a function that acquires, opens, mutates, or registers something it releases in the same body: each return, each raise, each call that can raise. An exit between the acquire and the release that skips the release is the defect: cover it with `try/finally`. An emit, a refusal branch, or a construction that sits after the acquire and outside the guard is such an exit: move it inside. A path releases a thing once: where an explicit release and the guard's release can both run on one path (a release, then a statement that can raise, inside a guard that releases again), the second release acts on a thing already gone and reports a failure that did not happen. Keep the guard's release, delete the explicit one, and let the branch leave through the guard. A `finally` or a second cleanup whose own raise replaces the exception in flight stands: Python chains the first exception to the second, and the owner frame's stack trace records both. A cleanup loop that abandons the rest on the first failure: attempt every item and raise the first failure after the loop. A cleanup loop that runs where a raise would land in unrelated code (a signal handler, an exit hook, a `finally` that already carries a failure in flight) attempts every item, records each failure as an event, and does not raise. | Fix here. Where unmasking lets a family escape that a caller in another file catches by the cleanup's name, record a unit on this function. A resource acquired in one function and released in another: record a unit on the acquiring function. |
| F2 | Catch out of position, silent, or short of its retry | Serves A4 at the owner frame, A2 where a read taken as absence leads to a write, A5 where a catch ends ongoing work, and A7 where a retry decision drops or skips accepted data. `.claude/rules/plumbline-coding.md` governs, at each catch, enumerated by one grep (`rg -n '^\s*(except\|finally)\b' <file>`) and judged by what its handler does, never by walking a callee for what it might raise. An owner frame, a member of the project's owner-frames subject, catches the top-level type and maps every raise to a recorded state under the practice the project's facts name for owner frames; an owner frame with no such catch is the defect: add the catch and the mapping in the shape the file's other owner frames of the same kind use. Every other catch stands only where its handler acts on the error: it retries within a budget, takes a different branch or returns a value the caller acts on, answers a specific status or refusal, or releases what it acquired and re-raises bare. A catch that logs or emits and continues with a default where no caller learns of the failure is the defect: re-raise bare, or delete the catch. A catch that only converts or only emits and re-raises is not a defect where it stands; never add one. A library's error that escapes a function to its owner frame is not a defect: never add a catch, a conversion, or a family tuple for it, and never widen a catch added for such an error to the library's whole family. A catch that stands and acts on a family catches the whole family (coding rule 4.3). A retry loop whose budget covers one failure branch of what it wraps: cover every branch. A catch inside a long-lived loop (a relay, a reporter, a reader of one line or one message at a time) that emits and continues stands where re-raising would end the loop for every later item. A test, a listing, or a catch that reads two failures as one value (an existence test, a directory test, or a search that answers "no" both for a thing that is missing and for a thing it could not examine; a missing file and an unreadable file both returned as "absent") and lets the caller overwrite or default on it: split the branches, and raise on the one that is not absence. | Fix here. Where a fix changes what a caller in another file catches by name, record a unit on this function. |
| F3 | Unbounded wait on foreign code | Serves A5, in a long-running process. A wait in an interactive command the user can interrupt stands. A thread join, a lock acquire, a condition wait, a barrier, a subprocess wait, or an arrival count that depends on foreign code (a script, a plugin, a callback, a spawned program, a thread that runs code this file did not write) arriving or returning, with no timeout and no way to notice that it never will. Enumerate every wait in the file and, for each, what it waits on and who writes that. Bound the wait, or count arrivals from what actually arrived rather than from what was started, report the member that never came by event, and continue as the function already does when a member is missing. | Fix here. Where the only way to take the new exit is a new raise or a new return value a caller in another file would see, or the bound or the count lives in another file, record a unit. |
| F4 | Success reported over an ignored failure | Serves A1 and A2 where a later write or delete trusts the false success, A3 where a user acts on it, and A7 where a failed commit, rewind, or delivery reads as done. A false success that only a log line reports, and nothing later trusts, stands. A cleanup or a removal that discards its errors (`ignore_errors=True`, `missing_ok` on a path the function expects to exist, a `\|\| true` in a shell file, an exit status never read) followed by an event, a message, or a return that reports the work done. Read the status, and report the failure in the shape the function already uses for its other failures. Whether a path is expected to exist is the caller's fact, never the helper's: where one removal helper serves callers that expect the path and callers that do not, the helper takes the expectation from its caller (a parameter, or two functions), and `missing_ok` stands only on the branch whose caller does not expect the path. Where the callers are in other files, record a unit on the helper. A shell function that reads a tool's failure exit as the tool's "no match" exit is the same defect: test the exit codes apart. | Fix here. |
| F5 | Ongoing work that one failure stops | Serves A5. List every piece of work in the file that repeats or runs without end: a thread body with a loop, a scheduled job, a queue or message consumer, a watcher, a poll loop, a serve loop. For each, list what can end it or stall it: a raise from one iteration that leaves the loop; one item whose failure the loop retries without end or blocks on, so no later item is reached; a wait with no bound on something that may never answer; a path on which it stops recording its state. The loop may end only on the stop it was built for. Catch at the iteration's edge, let the owner frame's event record the failure with its stack trace, and go on with the next iteration; set a failing item aside after its retry budget and go on with the next item; bound the wait and report the member that never came. | Fix here. Where the loop hands its failures to a caller in another file that ends it, or the item's budget lives in another file, record a unit. |
